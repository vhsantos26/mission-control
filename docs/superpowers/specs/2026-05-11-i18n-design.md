# i18n: Multi-language support (EN / PT-BR)

**Date:** 2026-05-11
**Status:** Approved

## Summary

Add English / Portuguese (PT-BR) language switching to the Mission Control UI, configurable in the Settings tab. Preference persists in `localStorage`. Default language: English.

## Architecture

All changes are confined to two existing files: `static/index.html` and `static/app.js`. No new files, no build step, no external dependencies.

### Core pieces (`app.js`)

| Piece | Description |
|---|---|
| `LOCALES` | Object `{ en: {…}, pt: {…} }` with ~66 keys, defined at the top of the file |
| `lang` | `let lang = localStorage.getItem('mc_lang') \|\| 'en'` |
| `t(key)` | `LOCALES[lang][key] ?? key` — falls back to the key itself, never throws |
| `applyLang()` | Iterates `[data-i18n]` elements → sets `textContent = t(key)`; also handles `data-i18n-placeholder` for inputs |
| Language toggle | `<select id="lang-select">` in Settings tab; on change → persist, update `lang`, call `applyLang()` + `refresh()` |

### Static strings (`index.html`)

Every element whose text is translatable gets a `data-i18n="key"` attribute. The visible text in the HTML source becomes the key name (or is removed entirely — the JS sets it on init). Elements with translatable `placeholder` or `title` attributes get `data-i18n-placeholder` / `data-i18n-title`.

### Dynamic strings (`app.js`)

All hardcoded strings in JS (chart series labels, table cell innerHTML, badge text) are replaced with `t('key')` calls. Since `refresh()` already re-renders all dynamic content, calling `applyLang()` + `refresh()` produces a full, instantaneous language switch.

### Number formatting

`fmt()` currently uses `toLocaleString("pt-BR")`. It becomes a regular function (not a `const`) that reads `lang` at call time:

```js
function fmt(n) {
  if (n == null) return "—";
  return Number(n).toLocaleString(lang === "pt" ? "pt-BR" : "en-US");
}
```

This means PT-BR renders `5.203.022` and EN renders `5,203,022`.

## Settings UI

The Settings tab gains a language row above the existing config text:

```
Language  [ English ▼ ]
```

The `<select id="lang-select">` has two `<option>` values: `en` (English) and `pt` (Português). On change, it persists to `localStorage('mc_lang')`, updates `lang`, calls `applyLang()` and `refresh()`. The select reflects the current `lang` on page load.

## Initialization sequence

1. `lang` is read from `localStorage` (default `'en'`)
2. `Promise.all([loadProjectFilter(), loadModelFilter()]).then(refresh)` — existing init
3. After DOM-ready, `applyLang()` is called once to translate all static elements
4. `lang-select` value is set to `lang`

## Constraints

- No bundler, no framework, no external i18n library — vanilla JS only.
- `data-i18n` attributes are the only HTML change beyond the Settings toggle element.
- `t()` must never throw — unknown keys fall back to the key string.
- Switching language must not require a page reload.
- The `fmt()` locale follows `lang` automatically.

## Out of scope

- More than two languages.
- Server-side locale (config.json, Accept-Language header).
- Translating data values returned by the API (project names, branch names, model names).
